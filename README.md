# smart-box

This workspace contains a GPL-licensed sing-box fork with an adaptive `smart`
outbound group and the Android client branch that consumes it.

> **Upstream notice:** smart-box is an independently maintained modified
> distribution of [SagerNet/sing-box](https://github.com/SagerNet/sing-box)
> and [SagerNet/sing-box-for-android](https://github.com/SagerNet/sing-box-for-android).

> are retained. See [UPSTREAMS.md](UPSTREAMS.md) for the exact imported bases.

## Smart outbound

`smart` keeps a short-lived destination-to-node memory, uses lazy URL probes to
seed latency scores, penalizes recent failures, avoids switching for small
score differences, and retries the remaining candidates when a dial fails.
Inactive groups do not probe at core startup or on interface changes. The first
real TCP/UDP use activates a delayed probe loop for that group, while explicit
URLTest requests still run immediately. Scores are stored in `cache.db` and
restored before the first connection after a restart. Recent failures retain a
short penalty, latency history decays to neutral over seven days, and each
background round combines the four best candidates with four rotating
exploration candidates so new nodes are not starved. One business connection
tries at most eight candidates with no more than two concurrent attempts;
failure penalties move bad nodes behind untried candidates instead of letting
every reconnect traverse a large Fallback pool.
The state is exposed through the existing outbound-group command stream, so
the Android groups screen can show the current candidate and per-node score.

```json
{
  "type": "smart",
  "tag": "Smart",
  "outbounds": ["node-a", "node-b", "node-c"],
  "url": "https://www.gstatic.com/generate_204",
  "interval": "5m",
  "tolerance": 50,
  "memory_timeout": "1h",
  "failure_penalty": 500,
  "score_namespace": "stable-profile-name",
  "score_identities": {"node-a": "node-config-fingerprint"},
  "interrupt_exist_connections": false
}
```

`interval` controls active probes. `tolerance` is the latency margin used to
avoid unnecessary switching. `memory_timeout` expires the per-destination
preference. `failure_penalty` is added to a node's score after a failed dial.
`score_namespace` isolates one product/profile family. `score_identities`
contains one-way candidate fingerprints generated by the smart-box converter;
changing one endpoint invalidates only that node and never puts server
credentials into the cache key.

## Product version

The client has its own release line. The current identity is:

```text
smart-box 0.1.1
based on sing-box 1.14.0-beta.14
```

The Smart version is user-facing and does not follow upstream semantic
versioning. The upstream version remains visible after it so compatibility is
still explicit.

## Go toolchain

The exact Go toolchain used for reproducible release builds is recorded in
[`TOOLCHAIN_VERSION`](TOOLCHAIN_VERSION), currently `go1.26.5`. Build and
verification scripts read this file rather than using the host's default Go
version. The imported `core/go.mod` intentionally keeps `go 1.25.5` as its
minimum language version; that minimum does not replace the exact release
toolchain pin.

## Build

### CachyOS Linux desktop client

The native Linux x86_64 release is built from `linux/`:

```bash
./linux/build-package.sh
cd dist/smart-box-0.1.1-linux-x86_64
./install.sh
smart-box
```

The PySide6 client provides status and traffic counters, Rule/Global/Direct/
`节能` modes, all 26 policy selectors with persistent regional choices, local
domain allow/proxy lists, subscription management, logs, tray operation, and
read-only Arch/CachyOS mirror benchmarking. Arch ranking covers official
packages from both pacman and paru; applying a ranking is an explicit,
root-authorized action with a pre-apply backup.
It manages `smart-box@<user>.service` and stops FlClash before every start or
restart. A normal smart-box stop leaves FlClash stopped. A failed takeover stops
smart-box and restores FlClash when it was the previous network owner. Startup
succeeds only after the service, TUN interface, local API, and five independent
network paths have passed two consecutive validation rounds.

The converter profile remains unchanged in `~/.config/smart-box/profile.json`.
The generated `runtime.json` uses the CachyOS-tested gVisor TUN stack, binds the
mixed and Clash API listeners only to localhost, filters provider status
pseudo-nodes, and installs `SmartBox` as the systemd-resolved default DNS link
for the service lifetime. See `linux/README.md` for installation and rollback
details.

The release artifacts are:

```text
dist/smart-box-0.1.1-linux-x86_64/
dist/smart-box-0.1.1-linux-x86_64.tar.gz
```

### Windows desktop client

Windows desktop client and bundled core:

```powershell
scripts/build-windows.ps1
```

The build produces
`dist\smart-box-0.1.1-core-1.14.0-beta.14-windows-x64\smart-box.exe`.
**Windows is not part of the 0.1.1 release**: the binaries cross-compile from
Linux and verify as PE32+, but have never been run on Windows hardware, so tray
startup, system proxy switching, and core restart are unverified. See
`ROADMAP.md`.

The client stores its single converter URL and validated profile under
`%LOCALAPPDATA%\smart-box`, runs in the notification area, controls the
bundled Smart core, and can switch the Windows system proxy at
`127.0.0.1:20808`. Existing settings and profiles are copied once from
`%LOCALAPPDATA%\sing-box-smart` when their smart-box counterparts are absent.

Generate the configuration schema after changing option types:

```powershell
$env:GOTOOLCHAIN = (Get-Content ..\TOOLCHAIN_VERSION -Raw).Trim()
go run .\cmd\sing-box schema -o .\docs\schema.json
```

The Android project is in `android/`. It uses the upstream
Gradle wrapper and expects Android SDK 37.1 and NDK `28.0.13004108`.

## Android runtime compatibility

The Android client rewrites every TUN inbound to the `gvisor` stack only in the
generated runtime profile. The downloaded converter profile is kept byte-for-
byte with its normal `mixed` stack, so the converter, Raspberry Pi, and Windows
client retain their platform-specific behavior. The Linux client independently
uses gVisor only in its own runtime copy after both `mixed` and `system` failed
the CachyOS TUN data-path test. These platform-local overrides avoid Android NAT
exhaustion and the separate Linux TUN forwarding failure without changing the
shared subscription.

The refreshed arm64 build is
`dist/smart-box-0.1.1-core-1.14.0-beta.14-android-arm64.apk`. Verify any
downloaded artifact with `sha256sum` and the release checksum file. It targets
`io.nekohasekai.sfa.smartbox`, but its default debug certificate is not
guaranteed to match an existing installation. For a device-signed build,
provide the keystore path explicitly:

```bash
ANDROID_KEYSTORE_PASS='...' ANDROID_KEY_ALIAS_PASS='...' \
  scripts/sign-android-device.sh input.apk output.apk /path/to/device.keystore
```

The resulting device-signed copy can update an installation when its
certificate matches. The repository does not contain a keystore or passwords.

Use the resulting signed APK to update an existing installation when its
certificate matches. A legacy variant for Android 5/6 was produced for 0.1.0
(`dist/smart-box-0.1.0-core-1.14.0-beta.14-legacy-android-5-arm64.apk`); it has
not been rebuilt for 0.1.1.

## Scope and limitations

The current implementation uses active URL-test latency for comparable node
scores and records business-connection success or failure separately. Node
quality scores and destination-to-node Smart memory persist in the cache across
core restarts; expired entries and failed-dial cooldowns are pruned before they
are reused. It does not collect packet-level retransmission statistics, so
scores remain a latency and connection-outcome signal rather than a full
transport-quality model.

## Raspberry Pi subscription converter

The Windows and Android clients are designed to consume a remote sing-box
profile URL, so the Raspberry Pi converter can remain the single place that
fetches and normalizes provider subscriptions. The deployed endpoint contract
is documented in `converter/README.md`:

```text
GET /subscription/<private-token>
Content-Type: application/json
```

The response is an ordinary sing-box profile with emoji-based regional Smart
groups, reachability filtering, last-known-good provider caches, and 26
selectors: one baseline plus 25 detailed policies covering AI, Telegram,
individual media platforms, social networks, games, development services,
vendor ecosystems, speed tests, downloads, domestic traffic, and ads. Every
policy can be pinned to suitable generated regional Smart groups. AI defaults
to a dedicated pool that excludes Hong Kong; other policies retain global and
regional choices. Shared AI, Telegram, media, and gaming Fallback pools avoid
duplicating active probes for every service.

The converter mirrors 39 validated binary SRS rule sets behind its private
endpoint, so clients do not depend directly on GitHub. Each service has a DoH
transport through its selected outbound, keeping DNS egress aligned with a
manual region choice. The profile includes Rule, Global, Direct, and an
energy-saving `节能` mode: energy saving keeps AI and Telegram on Smart while
routing other traffic and DNS directly. Android and Windows enable the core
cache file; the Raspberry Pi also persists its last validated profile and
rule cache under `/var/lib/smart-box`, allowing an offline converter restart.
The full matrix and ordering are in `converter/ROUTING.md`. Provider
credentials remain only on the Raspberry Pi.

Both clients accept one converter endpoint rather than provider subscriptions.
Android replaces its configuration list with protocol, host/IP, port, and a
single masked private path field and
validates the downloaded profile before replacing the current one. Software
auto-update, update-source, update-track, and APK installer features from the
upstream Android app are removed; remote profile refresh remains enabled every
30 minutes.

The Android fork uses application ID `io.nekohasekai.sfa.smartbox` and display
name `smart-box`. It can be installed alongside the official application
without sharing its app data. Remote-profile and file-import intent filters are
not registered. The Windows client uses separate process names and a separate
local data directory.
